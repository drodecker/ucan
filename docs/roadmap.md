# Roadmap

## Phase 0 — Problem definition

- Publish manifesto and motivation
- Define terminology
- Identify non-goals
- Document open questions
- Invite DNS and security review

## Phase 1 — Protocol exploration

- Define authorization record format
- Define operator identity format
- Define validation sequence
- Define revocation and key rollover
- Define resolver policy interfaces
- Produce threat model

## Phase 2 — Prototype

- Build authorization validator
- Build minimal UCAN-aware resolver
- Create example namespace operator
- Test DNSSEC integration
- Test multiple independent operator policies

## Phase 3 — Interoperability

- Publish test vectors
- Run multi-operator trials
- Document failures and conflicting interpretations
- Stabilize protocol version 0.1

## Phase 4 — Standards engagement

- Present to DNS operator communities
- Seek review from IETF participants
- Evaluate Internet-Draft submission
- Explore registry, registrar, ISP, and resolver pilots

## Phase 5 — Governance

- Define long-term stewardship
- Consider nonprofit foundation
- Evaluate whether any token, staking, or DAO mechanism is technically necessary
- Separate governance experimentation from the core protocol
